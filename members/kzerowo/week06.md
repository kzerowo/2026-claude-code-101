# Flare Alert — 6주 마무리

코인 **거래대금 급등 알림** 서비스. 관심 코인을 채널로 등록해 두면, 최근 거래대금이
그 코인의 평소 수준보다 비정상적으로 늘어날 때 브라우저 알림을 보낸다.

- 서비스: https://flare-alert-web-eight.vercel.app/
- 주차별 기록: [week01](week01.md) · [week02](week02.md) · [week03](week03.md) · [week04](week04.md)

## 무엇을 만들었나

| 구분      | 내용                                                                                 |
| --------- | ------------------------------------------------------------------------------------ |
| 웹        | Next.js 15 + Supabase (Vercel 배포) — 랜딩, 채널 관리, 알림 기록, 마이페이지, 관리자 |
| 감지 서버 | Node.js detector — Oracle Cloud 상시 실행 (systemd), 바이낸스 USD-M 선물 매초 감시   |
| 알림      | Web Push (RFC 8291 + VAPID) — 탭을 닫아도 도착                                       |
| 백테스트  | 과거 데이터 재생으로 기준값을 눈이 아니라 숫자로 정함                                |

판정 방식: 최근 N초 거래대금을 직전 같은 길이 구간들의 **중앙값**과 비교해,
정해진 **배수** 이상이면 알림. 민감도 슬라이더(1~100)가 감시 구간 길이와 배수를 함께 움직인다.

## 이번 주: 랜딩 페이지

**구성**: 히어로 → 실시간 급등 예시 애니메이션 → 왜 필요한가 → 작동 방식 3단계 →
**직접 움직여 보는 민감도 슬라이더** → 종목 크기와 무관한 같은 기준 → 민감도 테스트 →
**이 알림이 하지 않는 일** → 요금제 → FAQ

읽기만 하는 페이지가 아니라 실제 조절기를 페이지 안에 넣어, 슬라이더를 움직이면
하루 몇 번 울릴지 바로 보이게 했다. 그대로 민감도 테스트로 이어진다.

특히 **"이 알림이 하지 않는 일"** 섹션을 일부러 넣었다. 백테스트로 재어 보니
알림 이후 가격 방향은 거의 반반이었다. 매매 신호처럼 파는 편이 잘 팔리겠지만,
측정한 결과와 다른 말을 랜딩에 쓸 수는 없었다.

## 회고

**좋았던 것**

- **CLAUDE.md에 "결정과 그 이유"를 계속 적은 것.** 코드 구조가 아니라 왜 그렇게
  했는지를 남기니, 새 세션에서도 같은 논의를 반복하지 않았다. 6주간 가장 크게
  아낀 시간.
- **직접 만든 `dev` 스킬.** 웹과 detector 두 프로세스를 띄우는 방법을 스킬로
  적어 두니 "개발 서버 켜줘" 한 마디로 끝났다.
- **눈이 아니라 측정으로 기준을 정한 것.** 기본 민감도, 거래대금 하한을 감으로
  찍지 않고 백테스트로 재고 시간대 편향까지 보정했다. 랜딩 문구가 과장되지
  않은 것도 여기서 나왔다.

**어려웠던 것**

- **알림이 안 오는데 서비스는 멀쩡해 보였다.** 바이낸스 주소가 바뀐 걸 모르고
  옛날 주소로 계속 붙고 있었다. 시장이 조용해서 알림이 없는 건지 연결이 끊긴건지 화면으로는 구분이 안 됐다. 결국 "지금까지 받은 거래 건수"를 두 번 재서 숫자가 늘어나는지 봐야 알 수 있었다.
- **문서와 실제가 갈라질 때.** systemd가 잘못된 위치의 설정 키를 조용히 무시하는
  것처럼, 시킨 대로 됐다고 믿었다가 아닌 경우가 몇 번 있었다. 결국 확인은
  사람 몫이었다.

**남은 것**: 결제 연동, 모바일 앱, 감시 종목 확대.
